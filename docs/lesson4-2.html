lesson4-2 — Chat klient k nasadenému modelu

lesson4-2/chatclient.py — najjednoduchšia možná „lightweight chat client application“.

← Späť na prehľad  ·  Python pre C# programátora

Čo skript robí

Otvorí nekonečnú slučku v konzole. Do nej píšeš správy, skript ich posiela modelu nasadenému v Microsoft Foundry (napr. DeepSeek-V3.2, GPT-4o, Phi-4) a vypisuje odpoveď. Celá história konverzácie sa drží v pamäti procesu a posiela sa znovu pri každom volaní, takže model „si pamätá“, o čom bola reč. Ukončenie cez Ctrl+C.

Tok volania

config.env  →  OpenAI(base_url=endpoint, api_key=key)
             ↓
    conversation = [ {system}, {user}, {assistant}, {user}, ... ]
             ↓
    client.chat.completions.create(model=..., messages=conversation)
             ↓
    response.choices[0].message.content  →  výpis + pridanie do histórie

Rozbor kódu

1. Načítanie konfigurácie

CONFIG_FILE = "config.env"

def load_config():
    if not os.path.exists(CONFIG_FILE):
        ...sys.exit(1)
    load_dotenv(CONFIG_FILE)

python-dotenv načíta súbor config.env do premenných prostredia. Ide o bežný vzor „nikdy nemaj kľúč v zdrojovom kóde“. Funkcia get_required() potom každú povinnú premennú overí a pri chýbajúcej hodnote skončí s čitateľnou chybou.

2. Zostavenie klienta

client = OpenAI(
    base_url=f"{endpoint}",
    api_key=api_key,
)

Používa sa oficiálne OpenAI SDK, nie žiadna špeciálna Azure knižnica. Funguje to preto, že Foundry vystavuje OpenAI-kompatibilný inference endpoint — stačí prepísať base_url na svoj endpoint a api_key na kľúč z Foundry. Ten istý kód by po zmene dvoch reťazcov hovoril s api.openai.com.

3. Systémový prompt a história

system_prompt = os.getenv("SYSTEM_PROMPT", "You are a helpful assistant.")
conversation = [{"role": "system", "content": system_prompt}]

Zoznam conversation je zoznam správ s rolami. Prvá je vždy system — definuje správanie, tón a obmedzenia asistenta. Ďalej sa striedajú user a assistant.

4. Slučka

conversation.append({"role": "user", "content": user_input})

response = client.chat.completions.create(
    model=model,
    messages=conversation,
)
assistant_message = response.choices[0].message.content
conversation.append({"role": "assistant", "content": assistant_message})

Odpoveď modelu sa pridá späť do histórie. model= je názov deploymentu z Foundry, nie názov rodiny modelu.

Ošetrenie chyby robí jednu nenápadnú, ale dôležitú vec: pri zlyhaní volania sa posledná user správa conversation.pop()-ne, aby sa história nezanášala správami, na ktoré nikdy neprišla odpoveď.

Konfigurácia

Premenná Význam
AZURE_FOUNDRY_ENDPOINT URL inference endpointu deploymentu
AZURE_FOUNDRY_API_KEY kľúč k endpointu
AZURE_FOUNDRY_MODEL názov deploymentu modelu
SYSTEM_PROMPT voliteľný — správanie asistenta

Závislosti: openai, python-dotenv.

Čo z toho treba na skúšku

Doména: Implement generative AI apps and agents by using Foundry — konkrétne body „Deploy a model and interact with it“ a „Create a lightweight chat client application by using the Foundry SDK“.

  • Tri role správ. system = inštrukcie a osobnosť modelu, user = vstup človeka, assistant = odpoveď modelu. Toto je najčastejšia otázka z tejto oblasti.
  • Modely sú bezstavové. Model si nepamätá nič medzi volaniami. Pamäť konverzácie vzniká len tým, že klient posiela celú históriu znovu. Preto dlhá konverzácia stojí viac tokenov a raz narazí na limit kontextového okna.
  • Prompt engineering. Kvalitu odpovede ovplyvníš hlavne systémovým promptom — jasná rola, formát výstupu, obmedzenia, prípadne pár príkladov (few-shot).
  • Deployment vs. model. V API sa uvádza názov deploymentu. Jeden model môže mať viac deploymentov s rôznymi kvótami.
  • Kompatibilita. Foundry vystavuje OpenAI-kompatibilné API, preto sa dá použiť štandardné openai SDK s prepísaným base_url.
Parametre, ktoré sa v deme nepoužívajú, ale skúška ich pozná

temperature (0 = deterministické, vyššie = kreatívnejšie), top_p (nucleus sampling — meniť buď toto alebo temperature, nie oboje), max_tokens (strop dĺžky odpovede), stream=True (odpoveď po tokenoch, lepší pocit z latencie).

Typická otázka

Používateľ sa spýta „a čo tá predchádzajúca otázka?“ a model netuší, o čom je reč. Prečo?
→ Aplikácia neposiela históriu konverzácie v poli messages.

Kde nastavíš, že asistent má odpovedať len o cestovaní a vždy po slovensky?
→ V správe s rolou system.

Cvičné otázky

Odpoveď a vysvetlenie odkryješ kliknutím na „Ukázať odpoveď“.

  1. Ktorá rola v poli messages sa používa na určenie správania a tónu asistenta?

    • A. user
    • B. assistant
    • C. system
    • D. tool
    Ukázať odpoveď

    C — system. Systémová správa je prvá v konverzácii a definuje rolu, tón, formát výstupu a obmedzenia. user je vstup človeka, assistant odpoveď modelu.

  2. Aplikácia volá model pri každej otázke zvlášť a posiela len poslednú správu používateľa. Používateľ sa sťažuje, že model si nepamätá predchádzajúcu otázku. Čo je príčina?

    • A. Model má príliš malý počet parametrov.
    • B. Aplikácia neposiela históriu konverzácie v poli messages.
    • C. Je nastavená príliš nízka temperature.
    • D. Deployment nemá zapnutú pamäť.
    Ukázať odpoveď

    B. Modely sú bezstavové. Pamäť konverzácie vzniká výlučne tým, že klient pri každom volaní pošle celú doterajšiu históriu. Žiadne nastavenie „pamäte“ na deploymente neexistuje.

  3. Čo sa uvádza v parametri model pri volaní chat completions?

    • A. Názov rodiny modelu, napr. „GPT“.
    • B. Názov deploymentu vytvoreného v Foundry.
    • C. ID predplatného Azure.
    • D. Región, v ktorom je model hostovaný.
    Ukázať odpoveď

    B. Uvádza sa názov deploymentu. Jeden model môže mať viacero deploymentov s rôznymi názvami, kvótami a verziami.

  4. Model má generovať čo najpredvídateľnejšie, konzistentné odpovede pre automatizované spracovanie. Ktorý parameter a akú hodnotu nastavíš?

    • A. temperature blízko 0
    • B. temperature blízko 1
    • C. max_tokens na maximum
    • D. stream na True
    Ukázať odpoveď

    A. Nižšia temperature = menej náhodnosti = viac deterministické odpovede. Vyššia hodnota zvyšuje kreativitu a rozmanitosť. max_tokens obmedzuje len dĺžku, stream len spôsob doručenia.

  5. Používatelia sa sťažujú, že pri dlhých odpovediach sa dlho nič nedeje. Aká zmena najviac zlepší vnímanú odozvu bez zmeny modelu?

    • A. Znížiť top_p.
    • B. Zapnúť streamovanie odpovede (stream=True).
    • C. Pridať viac systémových správ.
    • D. Zvýšiť temperature.
    Ukázať odpoveď

    B. Pri streamovaní sa text zobrazuje po tokenoch hneď, ako vznikajú. Celkový čas sa nezmení, ale používateľ vidí odpoveď takmer okamžite.

  6. Konverzácia s modelom po dlhom čase začne zlyhávať s chybou o prekročení limitu. Prečo?

    • A. Vypršal API kľúč.
    • B. História konverzácie narástla nad veľkosť kontextového okna modelu.
    • C. Model sa automaticky odnasadil.
    • D. Systémový prompt je príliš krátky.
    Ukázať odpoveď

    B. Keďže sa posiela celá história, počet tokenov rastie s každým kolom. Riešením je skracovanie histórie (napr. len posledných N správ) alebo jej priebežná sumarizácia.

  7. Chceš, aby model vracal odpovede vždy vo formáte JSON s konkrétnymi kľúčmi. Kde to zabezpečíš najjednoduchšie?

    • A. Doladením (fine-tuning) modelu.
    • B. V systémovom prompte s popisom formátu a príkladom.
    • C. Nastavením max_tokens.
    • D. Zmenou regiónu deploymentu.
    Ukázať odpoveď

    B. Prompt engineering je prvá a najlacnejšia voľba. Fine-tuning je až posledná možnosť, keď prompt a príklady nestačia.

  8. Skript používa knižnicu openai, hoci model beží v Azure. Ako je to možné?

    • A. Knižnica sa automaticky pripojí k OpenAI a tá preposiela volanie do Azure.
    • B. Foundry vystavuje OpenAI-kompatibilný endpoint, stačí prepísať base_url a api_key.
    • C. Ide o chybu, malo by sa použiť iné SDK.
    • D. Funguje to len pre modely od OpenAI, nie pre DeepSeek či Llama.
    Ukázať odpoveď

    B. Inference endpoint v Foundry hovorí OpenAI-kompatibilným protokolom aj pre modely iných poskytovateľov, takže rovnaký klient obslúži DeepSeek, Llama aj Phi.

  9. Kde je v tomto riešení uložený API kľúč a prečo to tak je? Vyber najlepšie odôvodnenie.

    • A. Priamo v zdrojovom kóde — je to najrýchlejšie.
    • B. V súbore config.env, ktorý je mimo verzovania, aby sa tajomstvo nedostalo do repozitára.
    • C. V databáze aplikácie.
    • D. Kľúč nie je potrebný.
    Ukázať odpoveď

    B. Toto je princíp privacy and security zo zodpovednej AI. Ešte lepšie riešenie je nepoužiť kľúč vôbec a autentifikovať sa cez Microsoft Entra ID — pozri lesson4-4.
